# Swell

**Быстрый нативный клиент TIDAL с bit-perfect-воспроизведением Hi-Res.**

[![CI](https://github.com/oxakromax/swell-player/actions/workflows/ci.yml/badge.svg)](https://github.com/oxakromax/swell-player/actions/workflows/ci.yml)
[![Latest release](https://img.shields.io/github/v/release/oxakromax/swell-player)](https://github.com/oxakromax/swell-player/releases/latest)
[![License: GPL-3.0-or-later](https://img.shields.io/badge/license-GPL--3.0--or--later-blue)](COPYING)

![Swell показывает альбом; панель «Сейчас играет» закреплена справа](docs/screenshots/album.png)

</div>

Swell написан на Rust с использованием [gtk4-rs](https://gtk-rs.org),
[libadwaita](https://gnome.pages.gitlab.gnome.org/libadwaita/) и
[GStreamer](https://gstreamer.freedesktop.org/). Ваша библиотека открывается
мгновенно из локального кэша, Hi-Res FLAC доходит до звукового сервера
без изменений, а интерфейс подстраивается под любой размер окна, от
телефонного до широкого десктопного, при этом потребляя лишь малую долю
памяти по сравнению с другими клиентами ([замеры](#замеры)).

> [!NOTE]
> Swell не связан с TIDAL и не одобрен и не поддерживается TIDAL. Он
> использует неофициальные API TIDAL, которые могут измениться без
> предупреждения, и требует платной подписки TIDAL.

## Возможности

**Обзор**
- Главная: ваша персональная лента TIDAL (быстрый доступ, миксы,
  рекомендации, недавно прослушанное), подгружающая новое по мере
  прокрутки. Обзор: редакционные страницы, жанры, настроения и десятилетия.
- Поиск по мере ввода с фильтрами (треки, альбомы, исполнители, плейлисты),
  лучшим результатом, недавними запросами и постраничной загрузкой;
  вставленная ссылка TIDAL открывается.
- Страницы альбомов, исполнителей, плейлистов, миксов и радио: с данными об
  авторах, рецензиями, биографиями, похожими исполнителями и страницами
  «Показать все».
- Ссылки `tidal://` и `https://tidal.com/…` открываются в Swell.

**Ваша коллекция**
- Тысячи избранных треков с виртуализацией, мгновенной фильтрацией и
  сортировкой; избранные альбомы, исполнители, плейлисты и миксы; недавно
  прослушанное.
- Сердечки на всём (треки, альбомы, исполнители, плейлисты, миксы) — одним
  запросом для всей библиотеки.
- Создание, переименование, описание, публикация и удаление плейлистов;
  добавление треков из меню или перетаскиванием на плейлист в боковой
  панели; удаление и изменение порядка с возможностью отмены.

**Воспроизведение**
- Hi-Res Lossless (FLAC до 24 бит/192 кГц), [bit-perfect](#воспроизведение-bit-perfect).
- Воспроизведение без пауз, необязательный ReplayGain (по треку или
  альбому), выбор устройства вывода.
- Полноценная очередь: играть следующим, добавить в очередь, переход,
  удаление, изменение порядка, очистка с возможностью отмены;
  перемешивание, повтор всех/одного, история.
- Переживает сбои сети и истёкшие URL потоков, продолжая с той же позиции.
- Синхронизированные тексты песен, которые следуют за песней и перематывают
  по щелчку.
- Восстанавливает очередь и позицию при запуске; таймер сна; уведомления
  на рабочем столе; не даёт системе уснуть во время воспроизведения.
- MPRIS в Linux: работают медиаклавиши, виджеты рабочего стола и
  `playerctl`.

**Интерфейс**
- Дизайн libadwaita, следующий светлому/тёмному стилю и акцентному цвету
  системы, с тремя вариантами компоновки: широкая с закреплённой панелью
  «Сейчас играет», обычная и узкая с нижней панелью и мини-плеером.
- Полное управление с клавиатуры (Пробел, Ctrl+←/→, Ctrl+F, Ctrl+L, F6…;
  Ctrl+? показывает все комбинации клавиш) и доступные имена у каждого
  элемента управления.
- Доступен на одиннадцати языках (см. [Языки](#языки)).

## Установка

Пакеты для каждого выпуска находятся на
[странице выпусков](https://github.com/oxakromax/swell-player/releases).
Для Swell нужны GTK ≥ 4.18, libadwaita ≥ 1.7 и GStreamer с базовыми и
«хорошими» (good) плагинами; пакеты подтягивают их сами.

### Arch Linux (AUR)

Пакет AUR на подходе. А пока соберите тот же PKGBUILD из этого
репозитория:

```bash
git clone https://github.com/oxakromax/swell-player.git
cd swell-player/packaging/aur/swell-player   # or swell-player-git
makepkg -si
```

Когда он появится в AUR: `yay -S swell-player` (или `swell-player-git`).

### Flatpak

Скачайте пакет `.flatpak` со страницы выпусков и установите его (он
использует среду выполнения GNOME из Flathub). Публикация во Flathub
планируется.

```bash
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user ./swell-player-*.flatpak
flatpak run io.github.oxakromax.SwellPlayer
```

### Debian и Ubuntu

Требуется Debian 13 (trixie), Ubuntu 25.04 или новее (GTK ≥ 4.18 и
libadwaita ≥ 1.7). Скачайте `.deb` со страницы выпусков:

```bash
sudo apt install ./swell-player_*.deb
```

### Fedora

Скачайте `.rpm` со страницы выпусков:

```bash
sudo dnf install ./swell-player-*.rpm
```

### Windows

Скачайте установщик (или портативный `.zip`) со страницы выпусков. Сборки
пока не подписаны цифровой подписью, поэтому SmartScreen может предупредить
о нераспознанном приложении: выберите **Подробнее → Выполнить в любом
случае**.

### macOS

Скачайте `.dmg` со страницы выпусков и перетащите Swell в «Программы».
Приложение пока не нотаризовано, поэтому в первый раз щёлкните по нему
правой кнопкой мыши (или с нажатой клавишей Control) и выберите **Открыть**;
в macOS 15 и новее откройте его один раз, затем разрешите в **Системные
настройки → Конфиденциальность и безопасность → Всё равно открыть**. Так
как каждый выпуск подписывается ad hoc, после обновления macOS может снова
запросить доступ к записи Swell в связке ключей: выберите **Всегда
разрешать**. Ссылки `tidal://` в macOS пока не открывают Swell, а образ для
Intel (x86_64) собирается по возможности, поэтому в выпуске его может не
быть.

Сборки для Windows и macOS новее сборки для Linux: MPRIS и приведённые ниже
замечания о bit-perfect относятся только к Linux.

### Из исходного кода

Вам понадобятся Rust ≥ 1.96 ([rustup](https://rustup.rs), если в вашем
дистрибутиве версия старее), GTK ≥ 4.20 и libadwaita ≥ 1.8 (или GTK 4.18 и
libadwaita 1.7 с `--no-default-features`), GStreamer ≥ 1.24, SQLite и
`glib-compile-resources` из GLib.

<details>
<summary>Зависимости для сборки по дистрибутивам</summary>

```bash
# Arch Linux
sudo pacman -S --needed rust pkgconf gtk4 libadwaita sqlite \
    gstreamer gst-plugins-base gst-plugins-good

# Debian 13 / Ubuntu: their rustc is too old, so install Rust with rustup,
# and build with `make CARGOFLAGS=--no-default-features` where GTK is
# older than 4.20 (Debian 13 ships 4.18)
sudo apt install build-essential pkg-config libgtk-4-dev libadwaita-1-dev \
    libsqlite3-dev libglib2.0-dev-bin libgstreamer1.0-dev \
    libgstreamer-plugins-base1.0-dev gstreamer1.0-plugins-good

# Fedora
sudo dnf install cargo pkgconf-pkg-config gtk4-devel libadwaita-devel sqlite-devel \
    glib2-devel gstreamer1-devel gstreamer1-plugins-base-devel gstreamer1-plugins-good
```

`gst-plugins-good` содержит демультиплексор DASH (`dashdemux2`), который
используется для потоков Hi-Res.

</details>

```bash
make                  # cargo build --release --locked
sudo make install     # binary, desktop entry, icon, metainfo under /usr/local
```

`make install PREFIX=/usr DESTDIR=…` подготавливает установку для
упаковки, а `sudo make uninstall` удаляет её. Бинарный файл также
запускается прямо из `target/release/swell-player`, так как значки и
переводы встроены в него.

## Вход и качество звука

TIDAL не позволяет сторонним приложениям регистрировать собственные
OAuth-клиенты, поэтому Swell, как и любой клиент TIDAL с открытым кодом,
входит как одно из собственных приложений TIDAL. От выбранного способа
входа зависит, какое именно, а значит, и предельное качество:

| Вход | Как это работает | Наилучшее качество |
|---|---|---|
| **Браузер** (рекомендуется) | Swell открывает страницу входа TIDAL в вашем браузере. После входа TIDAL переходит на страницу с надписью «Oops»; скопируйте адрес этой страницы обратно в Swell. | **Hi-Res Lossless**: FLAC до 24 бит/192 кГц |
| **Код устройства** | Swell показывает короткий код; подтвердите его на `link.tidal.com` с любого устройства. | **Lossless**: FLAC 16 бит/44,1 кГц |

Качество стриминга выбирается в **Параметры → Воспроизведение**. Значок
формата в панели плеера показывает, что реально передаётся.

## Воспроизведение bit-perfect

При выключенной нормализации и громкости 100 % Swell сохраняет формат потока
вплоть до PipeWire: трек 24 бит/96 кГц доходит до него как 24 бит на
частоте 96 кГц. Значок формата в панели плеера открывает всплывающее окно,
где сказано, является ли вывод bit-perfect, а если нет — почему.

Дальше PipeWire решает, что получит звуковая карта. По умолчанию он
работает на одной частоте (часто 48 кГц) и ресемплирует всё остальное. Чтобы
он следовал частоте каждого трека, разрешите распространённые частоты,
например в `~/.config/pipewire/pipewire.conf.d/10-rates.conf`:

```
context.properties = {
    default.clock.allowed-rates = [ 44100 48000 88200 96000 176400 192000 ]
}
```

затем перезапустите PipeWire (`systemctl --user restart pipewire`). `pw-top`
показывает, что доходит до устройства.

## Языки

Swell говорит на **английском**, **испанском**, **французском**,
**немецком**, **итальянском**, **бразильском португальском**,
**русском**, **японском**, **корейском**, а также на **упрощённом** и
**традиционном китайском**. Он автоматически следует языку системы
(`LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`, как gettext), и это можно
изменить в **Параметрах**. Собственные материалы TIDAL (редакционные
тексты, заголовки страниц) запрашиваются на том же языке, поэтому на одном
экране никогда не смешиваются два языка.

Хотите Swell на своём языке? См. [docs/translating.md](docs/translating.md).

## Конфиденциальность

- **Токены** хранятся в системной связке ключей (в Linux — Secret Service:
  GNOME Keyring, KWallet, KeePassXC… или портал секретов во Flatpak) и
  никогда не лежат на диске в открытом виде. Они обновляются незадолго до
  истечения срока, а проблемы с сетью никогда не приводят к выходу из
  учётной записи.
- **Кэшируется на вашем компьютере:** ответы TIDAL и ваша библиотека
  (`~/.cache/swell-player/library.sqlite3`), обложки, ваши параметры,
  сохранённая очередь и недавние поисковые запросы. В параметрах кэш можно
  очистить; при выходе из учётной записи удаляются токены, кэш, сохранённая
  очередь и история поиска.
- **Никакой телеметрии.** Swell подключается только к серверам TIDAL — для
  того, что вы просите показать или воспроизвести. В нём нет аналитики,
  отправки отчётов о сбоях и других сторонних служб.

## Замеры

Swell в сравнении с [High Tide](https://github.com/Nokse22/high-tide) 1.6
(Python + PyGObject) на одном и том же компьютере, оба в безголовом сеансе
KWin (`kwin_wayland --virtual`, 1280×860) с сохранённым сеансом. Медианы по
трём запускам; память считывалась из `/proc` (RssAnon — собственная куча
приложения; RSS также включает общие библиотеки и около 250 МБ отображений
драйвера GPU, которые есть у любого приложения GTK 4). Показатели простоя
усреднены за 10 с без воспроизведения.

| | Swell | High Tide |
|---|---|---|
| Главная на экране: RssAnon / RSS | **61 МБ / 360 МБ** | 131 МБ / 504 МБ |
| 1 295 избранных треков на экране, из кэша | **0,42 с** после запуска (синхронизация с TIDAL — 0,50 с) | — ¹ |
| … без кэша Swell | первые 100 за **0,59 с**, все за 1,2–1,9 с | — ¹ |
| Вид «Избранное»: RssAnon / RSS | 85 МБ / 371 МБ | — ¹ |
| Загрузка ЦП в простое / пробуждения главного потока | ~0 % / 1,1 в секунду | ~0 % / 0,1 в секунду |
| Потоки | 15 | 19 |
| Hi-Res-трек выбран → звук | **0,67 с** (24 бит/96 кГц, доходит до PipeWire как S24_32 на частоте 96 кГц) | — |

¹ High Tide не кэширует избранное и не умеет открывать список избранного
напрямую; на тестовом стенде proof of concept Swell показал 13,3 с у High
Tide на отображение того же списка против 0,3 с у Swell.

Компьютер: Arch Linux, KDE Plasma 6 (Wayland), GTK 4.24, libadwaita 1.10,
GStreamer 1.28, Rust 1.99, релизная сборка.
